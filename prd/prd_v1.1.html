一、需求背景

1.1 现状问题

运营者计划在小红书开展教育行业内容运营，需在有限时间内完成数据复盘、文案与配图生产、历史笔记管理与发布辅助。v1.1 聚焦以下痛点（不包含内置合规引擎）：

  • 后台数据与选题参考分散，总览与 Top 笔记难一眼看清。
  • 竞品参考与模版结合后，文案版本管理与按官方结构预览仍耗人工。
  • 历史笔记指标与草稿组合缺少统一资产库。
  • 发布需在浏览器中逐项对齐官方创作页，易漏填、易错页。

1.2 为什么现在做

以「每周稳定产出、单条从打开工具到文案 + 可选图稿可预览定稿尽量短」为节奏目标，用一体化模块减少在总览、文案、配图、模版、笔记库、工作台与发布之间的切换；相册最终写入以辅助发布为主，失败或未映射位由运营在官方发布页补传。

约束声明（产品层）：多平台数据采集须遵守各平台用户协议与法律法规；本 PRD 要求实现上提供合法来源与人工导入等替代路径，不得以「无授权爬取」为唯一方案写死。浏览器辅助发布能力须与平台规则及账号安全策略一致，分阶段交付。

三、用户与使用场景

3.1 典型用户

主要用户：教育行业小红书内容运营者（可为个人或小团队）。阶段假设：同一人完成数据复盘、竞品参考与撰稿、模版维护、历史笔记同步、组合草稿、在工作台与发布页完成精修与发布辅助（v1.1 不含协作分工与自动发布）。

3.2 用户使用场景（摘要）

  • 数据复盘：在总览查看已发布/本周/优质笔记与 Top5 链接，对比近期表现。
  • 周中集中生产：模版 + 竞品生成文案多版本；在「图片生成与管理」据主文案生图并维护图稿池；在「工作台与发布」上半精修标题、正文与图片条。
  • 资产沉淀：同步小红书历史笔记与指标入库；将文案版本 + 所选图稿组合为新草稿，纳入笔记管理。
  • 发布前：在「工作台与发布」页用右侧手机预览核对后勾选确认，点击发布到小红书（网页版）打开创作平台浏览器端发布页并辅助填入；发草稿时再展开高级区选择对象（MVP，人工在官方网页最终点击发布）。

五、详细方案

v1.1 范围：总览、文案生成与管理、图片生成与管理、模版管理、笔记管理、工作台与发布。原型见 prototype_v1.1.html（5.7 iframe）。

5.1 竞品与模版输入

竞品材料须合法取得：支持粘贴摘要/正文，或在授权前提下由链接拉取。不可用时降级为仅模版生成。

5.2 文案子系统（模版 + 竞品参考 + 真人感）

模版：由「模版管理」维护（见 5.10）；生成页拉取启用中的模版。

竞品参考：与模版一并作为模型输入，输出差异化初稿并留存引用来源。

生成链路：竞品材料 + 选模版 → 真人感与模版约束 → 产出初稿（无内置合规扫描、无规则清单版本号）。

版本管理：每次生成新增文案版本；主版本标题与正文与「工作台与发布」编辑区双向同步。

5.3 图片生成与管理（生图 + 图稿池）

输入：当前内容条目的主文案（标题/正文摘要或关键句）+ 所选模版的视觉风格约束；每次生图须写入元数据 sourceCopyVersionId（点击生成瞬间的主文案版本），便于复盘「该图对应哪版文案」。

图稿池：同一条目下维护多张图稿（数量上限可配置）；支持新增；删除：若图稿 ID 仍被任一草稿快照引用，则禁止物理删除（可「从池隐藏」仅供历史快照展示，或引导用户先解除草稿引用）。支持 参与发布勾选、顺序（「工作台与发布」编辑区内拖曳或序号调整）、封面标星（见 5.6）。

联动：图稿池 ↔ 「工作台与发布」页编辑区图片条与快捷发布摘要（见 5.6：当前条目实时 / 草稿快照只读）；↔ 笔记管理组合草稿时的图稿多选。

5.4 工作台与发布（同一功能页：编辑 + 发布）

默认路径（当前条目）：左侧图文编辑区、中部手机预览与右侧发布区为同一功能页，与小红书浏览器版创作后台结构对齐。预览满意后，在发布区勾选「已核对预览」→ 点击发布到小红书（网页版）：在系统默认浏览器中新标签打开小红书创作服务平台对应的图文笔记发布 URL（如 creator.xiaohongshu.com/publish/imgNote，以平台当前入口为准），由实现层将本页标题、正文及（能力允许时）勾选图稿辅助填入；运营在官方网页登录后完成上传相册、话题等剩余项并点击官方「发布」。

从笔记管理载入：图文编辑区支持选择笔记管理中的已发布笔记或草稿，将对应标题与正文填充到当前条目的编辑区（并与「文案生成与管理」主文案区同源同步）。覆盖未保存编辑时建议二次确认（MVP 可简化为 Toast）。图稿池不因载入而替换，仍以「图片生成与管理」图稿池为准。右侧发布对象为当前条目时，载入后预览与快捷发布摘要随编辑区实时更新；发布对象为某草稿快照时，载入仅便于对照或改当前条目正文，不改变该草稿已固化的快照，除非用户在笔记管理中显式「从当前条目更新该草稿」。

草稿路径（高级）：从笔记管理选择待发布草稿时，展开「从草稿发布」区域，展示快照绑定的文案版本与图稿列表（只读）；仍须勾选预览已核对后再点击发布打开浏览器版官方页（填入内容以快照为准；可与左侧编辑区当前条目不一致，属预期）。

相册与封面：以图稿池中勾选参与发布的图片为主数据源，在编辑区展示缩略条并与手机预览一致；可选封面图 URL的规则见 5.6 封面与预览数据源表。

发布前校验：草稿路径下，不可在发布区切换为与快照不一致的文案版本；需变更须回条目重新组合草稿。当前条目路径下可与图稿池、主文案实时联动。

数据流与 MVP：文案主版本 ↔ 编辑区标题正文；图稿池 ↔ 编辑区图片条；内容设置与组件 ↔ 对浏览器版小红书发布页的辅助写入（目标字段、DOM 与扩展接口由 annex/ 维护）。MVP 可先「打开官方发布页 + 剪贴板同步标题/正文」；相册按序写入依赖浏览器扩展或受控自动化，受平台策略限制；未写入位由运营在网页端补传。最终点击「发布」必须在官方网页由人工完成。失败回草稿。

5.6 状态与一致性（草稿快照 · 发布校验 · 封面规则）

对象分层：内容条目拥有「主文案版本指针」「图稿池（含参与发布勾选、顺序、封面标星）」；笔记草稿（含组合生成）在创建或更新时写入不可变快照：snapshotCopyVersionId、orderedImageAssetIds[]、coverAssetId（可空）、optionalCoverPreviewUrl（可空，仅备忘）。后续条目内改池、改主版本不自动回写已存在草稿，除非用户显式「从当前条目更新该草稿」。

发布设置区行为：选择某草稿 → 文案版本与相册列表仅展示快照，与编辑区当前条目状态可能不一致属正常；选择当前条目 → 与图稿池、主文案实时一致。

0 张参与发布图稿：允许进入发布；相册位一律按「官方补传」处理；发布前预览首图使用 URL 占位（若有）或空白占位，并给出轻提示。

封面标星：在「参与发布」集合内至多一张标星为封面；若用户取消全部标星，则自动以参与发布顺序的第一张为封面。无参与发布图稿时，不设标星。

场景 笔记/封面预览首图 辅助发布写入相册第 1 张
存在参与发布图稿且已标星 标星图稿 标星图稿（写入失败则官方补传）
存在参与发布图稿但未标星（不应出现，系统应自动纠正） 参与发布顺序第 1 张 同左
无参与发布图稿、已填封面 URL 可用 URL 作预览占位 不写入 URL；官方本地上传
无参与发布图稿、无 URL 空白/占位图 官方本地上传

5.8 数据总览

已发布笔记总数、本周发布数、优质笔记数（浏览量阈值可配置）、待发布草稿数；Top 5 按浏览量及官方笔记链接。

5.9 笔记库与组合

历史笔记：官方接口或授权导出同步入库，存储标题、链接与各项互动指标及同步时间。

组合生成：选择文案版本与图稿池中的多张图（写入快照时固化顺序与 coverAssetId）→ 生成草稿；状态可标为「仅文案」「图文齐全」等。再次编辑条目图稿池不改变旧草稿快照，除非「更新草稿」显式操作。

5.10 文案模版管理

模版增删改、启用/停用、复制；元数据含名称、适用场景、段落结构说明等，供文案生成引用。

  IMG --> WB[工作台与发布: 编辑+预览+发布核对]
  D --> WB
  WB --> NB[笔记库: 历史同步与组合草稿]
  NB --> WB
  WB --> K[打开浏览器版创作发布页并辅助填入可写字段]
  K --> L[网页端补传相册等并人工点击官方发布]

可跳过配图：自「选模版+生成文案」可直接进入「工作台与发布」；此时图稿池可为空，走「仅文案 + 官方相册」路径。自「图片生成与管理」入池后，同一页内编辑区与发布设置区才参与相册辅助写入。

七、异常与边界处理

场景 处理策略
数据源不可用或不合规 提示使用人工导入/官方能力；禁止静默继续爬取
历史笔记同步失败或指标缺失 保留上次成功快照；单条标记「待补数」；支持手动编辑指标与重试同步
小红书页面结构变更导致辅助失败 草稿保留；错误码与日志；引导手动完成或等待适配
网络中断 自动保存草稿；发布辅助可重试
生图失败或额度用尽 提示原因；保留已有图稿池；允许跳过生图、仅用文案组合或官方页传图
删除图稿但已被草稿快照引用 禁止物理删除；提示解除草稿引用或「从池隐藏」；发布仍可按快照解析历史资源
参与发布勾选为空 允许继续；相册位全部为官方补传；预览按 5.6 表第 3/4 行
用户在「工作台与发布」发布设置区尝试切换与快照不一致的文案版本 草稿路径下禁止切换并提示「重新组合草稿」；当前条目路径允许
