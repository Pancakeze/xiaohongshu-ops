一、需求背景

1.1 现状问题

运营者计划在小红书开展教育行业（含 K12 相关）内容运营，需要在有限时间内稳定产出可发布内容，并完成配图与素材沉淀。当前痛点集中在：

  • 从多平台爆款与选题信号中提炼选题方向、拆解结构耗时长、难以标准化。
  • 文案需真人感且符合平台教育/K12 规则，纯模板或泛化生成易踩线或「AI 腔」明显。
  • 配图需与文案一致且可管理，需与文案绑定，并按学科系列、学期、年级归档，且支持跨学科引流多标签。
  • 发布链路希望由工具在浏览器中辅助填图填文；起步阶段人工审核与人工发布，未来在可控前提下演进为自动化审核与发布。

1.2 为什么现在做

以「每周 5 条、单条从打开工具到文案+配图初稿约 10 分钟」为节奏目标，需要一体化工具减少上下文切换（分析 → 撰稿 → 生图 → 素材归档 → 平台侧辅助发布），并将合规扫描与风险提示嵌入流程，降低运营与账号风险。

约束声明（产品层）：多平台数据采集须遵守各平台用户协议与法律法规；本 PRD 要求实现上提供合法来源与人工导入等替代路径，不得以「无授权爬取」为唯一方案写死。浏览器辅助发布能力须与平台规则及账号安全策略一致，分阶段交付。

三、用户与使用场景

3.1 典型用户

主要用户：教育行业小红书内容运营者（可为个人或小团队）。阶段假设：同一人完成数据复盘、竞品参考与撰稿、模版维护、生图、历史笔记同步、组合草稿、合规确认与发布（团队权限可后置）。

3.2 用户使用场景（摘要）

  • 数据复盘：在总览查看已发布/本周/优质笔记与 Top5 链接，对比近期表现。
  • 周中集中生产：用「模版管理」维护的结构模版 + 竞品链接或粘贴文案生成多版本；配图入库后在「笔记工作台」精修，并按系列/学期/年级归档。
  • 资产沉淀：同步小红书历史笔记与指标入库；将新生成的文案与图稿「组合」为新草稿，纳入笔记管理。
  • 发布前：在「发布笔记」从笔记管理选中目标笔记，预览后核对映射，辅助写入官方创作页，由人工最终点击发布（MVP）。

五、详细方案

本章描述核心业务规则与数据关系；已补充笔记工作台 / 发布辅助的原型 iframe 切片（见 5.7）。其余模块的交互级 Mermaid 可继续迭代。

5.1 信号采集与分析子系统

前置条件：用户具备合法数据使用权或提供可分析材料（链接、脱敏导出、人工粘贴正文等）。

核心输出：

  • 选题方向：若干可选角度，每条含证据摘要（来源、时间、平台）。
  • 爆款结构拆解：可映射到模版字段（如钩子、步骤、案例槽位、引导话术等）。

数据流：合法输入 → 清洗与去标识化（如需要）→ 结构化特征提取 → 报告对象（可关联到「内容条目」草稿）。

业务规则：默认不存储敏感个人信息；引用竞品原文需提示版权与转载风险；若数据源不可用，降级为「仅人工输入 + 模版生成」。

5.2 文案子系统（模版 + 竞品参考 + 真人感 + K12）

模版：由「模版管理」维护（见 5.10）；生成页拉取启用中的模版。

竞品参考：支持填写竞品笔记链接（在合法授权下拉取正文）或直接粘贴竞品文案摘要；与模版一并作为模型输入，输出差异化初稿并留存引用来源。

生成链路：竞品材料 + 选模版 → 应用「平台公开规则摘要」与「可更新清单」作为硬约束与软提示 → 产出初稿 → 合规扫描。

新生成文案的体现与管理：每次生成产生一条文案版本记录（时间戳、模版、规则版本号）；用户可切换主版本。当前主版本的标题 + 正文与笔记工作台（见 5.3a）双向同步，保证「生成 → 按小红书版式预览与微调」同一条目内闭环。

K12 规则落地：规则来源为平台公开文档摘要；清单由运营定期人工更新（版本号、更新人、生效时间）。生成与扫描均需记录当时生效的规则版本，便于复盘。

5.3 配图子系统（AI 生图）

绑定关系：每条「内容条目」维护图稿池（多张、多版本）；支持「参与发布」勾选、顺序号、封面标星（首图）。图稿池与笔记工作台图片条、发布辅助选图列表数据一致。

业务规则：生图提示词由文案关键信息 + 模版视觉风格约束拼接；用户可迭代重生成并保留版本历史；未勾选参与发布的图仅保留在池中，不写入浏览器发布页相册序列。

5.3a 笔记工作台（与小红书创作页结构对齐）

定位：运营台内嵌的「准官方」编辑与预览中枢，字段分区与小红书 Web 创作后台同构（图片编辑区、标题/正文、话题与活动话题、内容设置含合集/原创/AI 合成声明、添加组件如位置/分类/附件等），右侧提供笔记预览 / 封面预览切换。

数据流：文案主版本 ↔ 工作台标题正文；图稿池勾选序列 ↔ 工作台缩略图条；内容设置与组件 ↔ 发布辅助映射表中的目标字段。

5.3b 新生成图片的体现与管理

新生成图片以图稿形式进入当前条目的图稿池，在「AI 配图」页可管理版本、勾选是否参与发布；同步反映在「笔记工作台」图片条（如 x/18 计数）与「发布辅助」预览中。

5.4 素材归档与标签

维度：系列（数学/英语/物理等）、学期、年级、跨学科引流标签（多选）。

规则：一条内容必须至少一个系列或明确标记为「综合」；学期与年级为必选字段（可枚举可配置）。跨学科标签用于检索与推荐，不改变主系列归属逻辑（主系列单选 + 多标签）。

5.5 合规扫描（机器审核）

定义：合规扫描 + 风险提示（不含全面事实核查）。输出包含：命中规则条目、严重级别、修改建议、是否阻断发布辅助。

与发布关系：MVP 下高风险默认阻断「一键写入浏览器」直至用户显式确认「已知风险继续」（需二次确认并写审计日志）。具体阈值待原型阶段与运营共定。

5.6 发布笔记与自动化策略

发布对象：用户从笔记管理中选定一条待发布笔记（含组合生成的草稿）。

发布前选择：可再指定或覆盖文案版本与参与发布的图片集合及顺序（若草稿已绑定则默认带出）；在发布页切换笔记预览 / 封面预览核对效果。

字段映射（一一对应）：维护「小红书官方发布页字段 → 运营台数据源」映射表（含相册 1…N、标题、正文、话题/活动、合集、原创与 AI 声明、位置、分类、附件等）。执行「辅助发布」时按映射将值写入浏览器 DOM 对应控件（选择器随官方改版可配置）。

MVP：仅辅助填充至官方页草稿态；最终「发布」由人工在官方页点击。异常（网络、选择器失效、页面改版）→ 内容状态回退为草稿并提示重试路径。

未来：机器发布总开关关闭时禁止任何自动点击发布；开启时需满足合规扫描策略与配额；失败一律草稿。

5.8 数据总览

展示已发布笔记总数、本周发布数、优质笔记数（默认浏览量大于 1 万，阈值可配置）、待发布草稿数。提供按浏览量排序的 Top 5 笔记列表，每条含标题摘要与小红书笔记链接，支持跳转核对。

5.9 笔记库与组合

历史笔记：通过官方开放能力、授权数据导出或合规方式同步入库，持久化存储标题、链接、浏览量、点击率、观看量、点赞、收藏、评论、涨粉等指标及同步时间。

组合生成：用户在图稿池与文案版本中多选素材，生成新的「笔记草稿」实体，进入草稿列表，可再进入笔记工作台编辑，并进入发布笔记流程。

5.10 文案模版管理

模版与「文案生成与管理」共用数据源：支持创建、编辑、复制、启用/停用；模版元数据包含名称、适用场景、段落结构说明、禁用营销类型等，供生成与 K12 校验引用。

七、异常与边界处理

场景 处理策略
数据源不可用或不合规 提示使用人工导入/官方能力；禁止静默继续爬取
历史笔记同步失败或指标缺失 保留上次成功快照；单条标记「待补数」；支持手动编辑指标与重试同步
